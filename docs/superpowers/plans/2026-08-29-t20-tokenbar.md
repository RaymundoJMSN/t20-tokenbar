# t20-tokenbar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Um módulo Foundry que patcha o Monk's TokenBar de fora para dar compatibilidade real com Tormenta20: subir de nível de verdade, inspiração do `t20-inspiracao` na barra, stats separados para mestre e jogadores (jogador vê o texto do Health Estimate) e o modificador do ator no diálogo de testes.

**Architecture:** Módulo ESM sem build, carregado depois do `monks-tokenbar`, que importa as classes dele pela mesma URL (logo, a mesma instância de módulo). Dois `override` em `Tormenta20Rolls.prototype`, uma subclasse de `EditStats` e quatro hooks nativos. Toda a diferença visual entre mestre e jogador acontece num único passo de pós-render (`renderTokenBar`), porque o pipeline interno do monks lê stats por ficha antes do fallback global e vazaria o PV exato.

**Tech Stack:** JavaScript ESM puro (sem npm, sem bundler), Foundry VTT v13 (ApplicationV2, DialogV2), sistema Tormenta20.

## Global Constraints

- Foundry `compatibility.minimum: "13"`, `verified: "13"`.
- Sistema obrigatório: `tormenta20`. Módulo obrigatório: `monks-tokenbar` (em `relationships.requires`).
- `healthEstimate` e `t20-inspiracao` são **opcionais**: nunca em `requires`, sempre checados com `game.modules.get(id)?.active` antes de usar.
- Zero dependências npm, zero build. O que está no repo é o que o Foundry carrega.
- Todo texto de UI em português do Brasil.
- ID do módulo: `t20-tokenbar`. Prefixo de classes CSS e de `data-*`: `t20tb-`.
- Dev: `X:\FoundryVTT\Data\modules\t20-tokenbar` é junction para `C:\Users\rayna\Soltos\t20-tokenbar`. Editar `.mjs` exige F5 no Foundry; `.css` recarrega sozinho via `hotReload`.
- Único teste automatizado do projeto: `node scripts/regras.mjs --check`. O resto é verificação manual no Foundry, descrita passo a passo em cada tarefa.
- Toda mensagem de commit termina com `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

```js
/** Nível máximo do T20. `xpPorNivel` tem 20 posições e `getLevelExp` faz min(nivel, 19), então no
 *  nível 20 `xp.proximo` congela em 190000 e a comparação ficaria verdadeira para sempre. */
export const NIVEL_MAX = 20;

/** Um personagem só sobe se tem nível, não chegou ao teto e o XP alcançou o próximo marco. */
export function podeSubir(nivel, xp, proximo) {
  nivel = Number(nivel) || 0;
  xp = Number(xp) || 0;
  proximo = Number(proximo) || 0;
  return nivel >= 1 && nivel < NIVEL_MAX && proximo > 0 && xp >= proximo;
}

/** Itens de classe da ficha, na forma que o diálogo de escolha usa. */
export function classesDe(items) {
  return Array.from(items ?? [])
    .filter((i) => i?.type === "classe")
    .map((i) => ({ id: i.id, nome: i.name, niveis: Number(i.system?.niveis) || 1 }));
}
```

- [ ] **Step 1: Escrever os dois overrides**

Acrescentar em `scripts/main.mjs`, dentro do `Hooks.once("init", ...)` que já existe:

```js
Hooks.once("init", () => {
  console.log(`${MOD} | init`);
  patchesDoSistema();
});

function patchesDoSistema() {
  /* O monks devolve null aqui, então o diálogo de teste mostra o nome do ator sem modificador.
     No T20 resistências SÃO perícias — é o mesmo rollPericia no roll() do tormenta20-rolls.js —
     então 'save' e 'skill' caem os dois em system.pericias. */
  Tormenta20Rolls.prototype.getValue = function (actor, type, key) {
    const src = type === "ability" ? actor?.system?.atributos : actor?.system?.pericias;
    return src?.[key]?.value;
  };

  /* Só soma o XP. O sussurro original do monks dizia "você subiu de nível" e não subia nada;
     quem oferece o nível agora é o hook updateActor (ver nivel.js nesta mesma pasta). */
  Tormenta20Rolls.prototype.assignXP = async function (msgactor) {
    const actor = game.actors.get(msgactor.id);
    if (!actor) return;
    const atual = Number(actor.system?.attributes?.nivel?.xp?.value) || 0;
    await actor.update({
      "system.attributes.nivel.xp.value": atual + (Number(msgactor.xp) || 0)
    });
  };
}
```

- [ ] **Step 1: Criar `scripts/nivel.mjs`**

```js
/**
 * Subir de nível de verdade no T20.
 *
 * O nível é derivado: prepareBaseData recalcula system.attributes.nivel.value como a soma de
 * system.niveis dos itens 'classe'. Escrever nivel.value não persiste — subir é +1 em niveis.
 */
import { podeSubir, classesDe } from "./regras.mjs";

let MOD = "t20-tokenbar";

export function ativarNivel(id) {
  MOD = id;
  Hooks.on("updateActor", aoMudarXP);
  Hooks.on("renderChatMessageHTML", ligarBotao);
}

/** Só o GM ativo cria o card, senão cada cliente criaria o seu. */
function aoMudarXP(actor, changes) {
  if (!game.user.isActiveGM) return;
  if (actor.type !== "character") return;
  if (!foundry.utils.hasProperty(changes, "system.attributes.nivel.xp.value")) return;
  if (!game.settings.get("monks-tokenbar", "send-levelup-whisper")) return;
  oferecerNivel(actor);
}

function dadosDeNivel(actor) {
  const attrs = actor.system?.attributes?.nivel ?? {};
  return {
    nivel: Number(attrs.value) || 0,
    xp: Number(attrs.xp?.value) || 0,
    proximo: Number(attrs.xp?.proximo) || 0
  };
}

async function oferecerNivel(actor) {
  const { nivel, xp, proximo } = dadosDeNivel(actor);
  if (!podeSubir(nivel, xp, proximo)) return;
  const alvo = nivel + 1;

  // Já existe card em aberto para este nível? O alvo sobe junto com o nível, então um card antigo
  // de nível 4 não bloqueia o card de nível 5.
  const recentes = game.messages.contents.slice(-50);
  if (recentes.some((m) => m.getFlag(MOD, "ator") === actor.uuid && m.getFlag(MOD, "nivelAlvo") === alvo)) return;

  const destinatarios = game.users
    .filter((u) => u.isGM || actor.testUserPermission(u, "OWNER"))
    .map((u) => u.id);

  await ChatMessage.create({
    content: `<div class="t20tb-nivel">
      <p><b>${foundry.utils.escapeHTML(actor.name)}</b> tem XP para o nível ${alvo}.</p>
      <button type="button" class="t20tb-subir">Subir de nível</button>
    </div>`,
    whisper: destinatarios,
    flags: { [MOD]: { ator: actor.uuid, nivelAlvo: alvo } }
  });
}

function ligarBotao(message, html) {
  const btn = html.querySelector(".t20tb-subir");
  if (!btn) return;

  const actor = fromUuidSync(message.getFlag(MOD, "ator") ?? "");
  const alvo = Number(message.getFlag(MOD, "nivelAlvo")) || 0;
  const { nivel, xp, proximo } = actor ? dadosDeNivel(actor) : {};

  // Card velho (já subiu, ou XP mudou) vira texto. Não depende de flag 'resolvido' porque o
  // jogador não pode editar uma mensagem criada pelo GM.
  if (!actor || nivel >= alvo || !podeSubir(nivel, xp, proximo)) {
    btn.replaceWith(Object.assign(document.createElement("em"), { textContent: "Já resolvido." }));
    return;
  }
  if (!game.user.isGM && !actor.isOwner) {
    btn.remove();
    return;
  }

  btn.addEventListener("click", () => subirNivel(actor, alvo));
}

async function subirNivel(actor, alvo) {
  const { nivel, xp, proximo } = dadosDeNivel(actor);
  if (!podeSubir(nivel, xp, proximo) || nivel >= alvo) {
    return ui.notifications.warn(`${actor.name} não tem XP para subir agora.`);
  }

  const classes = classesDe(actor.items.contents);
  if (!classes.length) {
    return ui.notifications.warn(`${actor.name} não tem nenhuma classe na ficha — adicione uma antes de subir.`);
  }

  let escolha = classes[0];
  if (classes.length > 1) {
    const opcoes = classes
      .map((c) => `<option value="${c.id}">${foundry.utils.escapeHTML(c.nome)} ${c.niveis} → ${c.niveis + 1}</option>`)
      .join("");
    const id = await foundry.applications.api.DialogV2.prompt({
      window: { title: `Subir para o nível ${alvo}` },
      content: `<p>Qual classe sobe?</p><select name="classe" style="width:100%">${opcoes}</select>`,
      ok: { label: "Subir", callback: (_ev, botao) => botao.form.elements.classe.value },
      rejectClose: false
    });
    if (!id) return;
    escolha = classes.find((c) => c.id === id) ?? escolha;
  }

  await actor.items.get(escolha.id)?.update({ "system.niveis": escolha.niveis + 1 });

  await ChatMessage.create({
    content: `<b>${foundry.utils.escapeHTML(actor.name)}</b> subiu para o nível ${alvo} (${foundry.utils.escapeHTML(escolha.nome)} ${escolha.niveis + 1}).`
  });
}
```

```js
function pontosDe(actor) {

}

/**
 * Troca a coroa booleana do dnd5e (apps/tokenbar.js:616 lê system.attributes.inspiration) pelo
 * número real do t20-inspiracao. O atributo inspiration="true" é o que o CSS do monks usa para
 * sair do display:none (css/tokenbar.css:411).

function marcarInspiracao(li, actor) {
  if (!temInspiracao()) return;
  if (!game.settings.get(MTB, "show-inspiration")) return;
  const icon = li.querySelector(".inspiration-icon");
  if (!icon) return;

  const n = pontosDe(actor);
  const cap = Number(game.settings.get(INSP, "capMax")) || 0;
  icon.setAttribute("inspiration", n > 0 ? "true" : "");
  icon.replaceChildren();
  const crown = document.createElement("i");
  crown.className = "fas fa-crown";
  const num = document.createElement("span");
  num.className = "t20tb-n";
  num.textContent = String(n);
  icon.append(crown, num);
  icon.removeAttribute("title");
  icon.dataset.tooltip = `${actor.name}: ${n}/${cap} inspiraç${n === 1 ? "ão" : "ões"}`;
}

/** Acha a entrada da barra correspondente a um <li.token>. */
function entradaDo(app, li) {
  const { tokenId, actorId } = li.dataset;
  return app.entries?.find((e) => (tokenId && e.token?.id === tokenId) || (actorId && e.actor?.id === actorId));
}

Hooks.on("renderTokenBar", (app, element) => {
  for (const li of element.querySelectorAll("#token-action-bar .token")) {
    const entry = entradaDo(app, li);
    if (!entry?.actor) continue;
    marcarInspiracao(li, entry.actor);
  }
});

/* O monks só re-renderiza quando o diff dele muda, e ele não olha para a flag do t20-inspiracao. */
Hooks.on("updateActor", (actor, changes) => {
  if (foundry.utils.hasProperty(changes, `flags.${INSP}.pontos`)) MonksTokenBar.tokenbar?.render();
});
```

```js
    game.settings.set(MOD, "stats-jogador", this.stats);
    MonksTokenBar.tokenbar?.refresh();
    this.submitting = true;
```

```js
/**
 * Estimativa do healthEstimate para um TokenDocument, ou null.
 *
 * getEstimation (healthEstimate.js:4020) usa token.document, token.actor e token.combatant —
 * precisa do placeable, não do TokenDocument; daí o .object. As duas guardas espelham
 * _handleOverlay (linha 3783): se o healthEstimate esconde a estimativa daquele usuário no canvas,
 * esconde aqui também, senão este mod vira um bypass das configurações dele.
 */
function estimativa(tokenDoc) {
  const he = game.healthEstimate;
  const t = tokenDoc?.object;
  if (!he || !t?.actor) return null;
  try {
    if (he.breakOverlayRender(t)) return null;
    if (!game.user.isGM && he.hideEstimate(t)) return null;
    const { desc, color } = he.getEstimation(t) ?? {};
    if (desc === undefined || !color) return null;
    const { estimate } = he.getStage(t, he.getFraction(t)) ?? {};
    return { desc, color, faixa: Math.clamp(Number(estimate?.value) || 0, 0, 100) };
  } catch {
    return null; // token sem PV numérico, ator sem ficha etc.
  }
}
```
